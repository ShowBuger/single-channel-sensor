# FIELD · 本地 Web 上位机

双击 `启动上位机.cmd`（或 `FIELD.exe`）。本地服务自动打开 HTML 界面，串口窗口自动扫描 Windows COM 端口，只需选择端口号与波特率。无需安装 Python、Node.js、npm 或网络依赖；通信程序使用 Windows .NET Framework。

更新程序后请关闭旧的 FIELD 窗口，再重新启动。`FIELD.exe` 与 `index.html`、`core.js`、`app.js`、`bridge-client.js`、`import-ui.js` 必须放在同一目录。单独双击 HTML 可以离线预览，但不能枚举或连接设备。

## 导入配置与设备读回

1. 连接设备，默认波特率 `921600`（旧版默认值自动迁移，仍可手动选择其他速率）。在 **导入配置** 窗口勾选 **自动加载配置** 后，连接时读取下位机完整配置；已连接时勾选也会立即读取。取消勾选不会主动读取。该选项不再从浏览器恢复参数。
2. 点击顶部导航 **导入配置**，原参数配置表及工具栏重复入口已移除。可选择 JSON 文件、直接粘贴，或点击 **读取设备配置**。
3. 检查产品型号、传感器参数、算法参数和日志等级预览。修改内容后点击 **校验配置**。设备读取值标注“设备读回”，文件值和编辑值单独标注。
4. 检查默认补全项：**省略字段会恢复固件默认值，不会保留设备旧值**。
5. 点击 **应用到设备**。默认勾选“应用后启动采集”，会执行启动及标定。
6. 等待设备保存确认及完整配置逐项读回校验。传输阶段可取消；提交应用后不可取消或自动回滚。

导入文件只生成预览，不会立即发送。读取配置不会保存 Flash、启动采集或标定。未连接时仍可校验、下载默认模板和导出配置。“导出配置”导出的是当前编辑区已校验的配置；读取设备后可直接导出作为备份。传感器字段代表下位机配置值，并非芯片寄存器的 I2C 读回。

**需更新下位机固件**：旧版 `ML GETCFG` 回包截断且缺少日志等级，不能支持完整读取。新固件已生成在 `firmware/build/single_channel_sensor.hex`（同时生成 `.bin` / `.elf`），本次未自动烧录。导入前会检测完整读取能力，旧固件会提示升级并停止写入，不会拿默认值冒充设备读回值。

旧固件回复 `Unknown: ML IMPORT_CANCEL` 时，连接流程会识别为不支持配置导入并继续接收采样数据，不再等待超时。完整配置读取失败会保留连接并说明升级要求。真正未收到确认的命令超时仍会关闭连接，但错误提示保留具体命令、等待时间和最后回复，便于排查。

支持仓库 `firmware/config/config_example.json`，以及旧版 `tools/sensor_config.json`。长键名、旧版 `algorithm` 分组会转换成固件支持的短键名。拒绝未知字段、重复别名、非整数寄存器值、范围错误和非有限 float32 数值。JSON 文件须符合标准语法，不支持注释。

顶层 `product` 为产品型号字符串，对应固件 `product_model[8]`，允许 1–7 个 ASCII 字母、数字、下划线、点或短横线。缺失时补为 `MA01`，预览标注“默认补全”；模板、导出和下发均保留该字段。设备完整读回必须包含实际 `product` 值，应用后进行字符串逐字比较。下位机 JSON 接收解析已补齐该字段，需要更新固件后才能导入保存。

```json
{
  "product": "MA01",
  "sensor": {"gain":7,"osr":3,"filt":0,"resx":0,"resy":0,"resz":0,"tcmp":0},
  "algo": {"flag":"0x3B","xmap":0.1,"ymap":0.1,"zmap":-0.1,"dead":8.5,"spike":20,"stab":0.1},
  "log": {"level":3}
}
```

| 分组 | 参数与范围 |
| --- | --- |
| product | 顶层产品型号字符串，1–7 个字母、数字、下划线、点或短横线，默认 MA01 |
| sensor | gain 0–7、osr 0–3、filt 0–7、resx/resy/resz 0–3、tcmp 0–1；均为整数 |
| algo | flag 0–255 或十六进制字符串；映射系数、死区/尖峰倍数、稳定性阈值为有限 float32 数值 |
| log | level 0 NONE、1 ERROR、2 WARN、3 INFO、4 DEBUG |

**当前固件以 INFO 等级输出采样值。日志等级设为 0–2 时，不会输出实时曲线数据。** 上位机支持 `[I][DATA] sensor0:...` 及旧版无日志前缀数据。

## 当前固件协议兼容

基于 `45f28d4`（JSON 导入）、`2d39088`（分级日志），并修复 `firmware/src/main.c` 中的完整配置读取接口：

- 命令串行发送，按 `READY → ACK_<累计字节数> → IMPORT_OK` 等待并验证响应。
- UART 命令缓冲区为 64 字节；每块使用 **47 个 ASCII 字节**，加 15 字节前缀后共 62 字节。
- 规范化 JSON 不超过 **1023 字节**，为固件终止符留出空间。
- 连接设备后及导入前发送 `ML IMPORT_CANCEL` 清理遗留会话。完成或报错后再次发送 CANCEL：当前固件在 COMPLETE / ERROR 状态仍将所有命令交给导入模块，必须复位状态后才能恢复常规命令。此 CANCEL 不撤销已应用的配置。
- 超时或断线不会自动重发写入，防止重复应用。部分应用失败会提示核对设备状态；重新导入会先重置导入会话。
- `ML GETCFG` 返回 `CFG_BEGIN\r\n`、一行完整 JSON、`\r\nCFG_END\r\n`。JSON 包含全部 sensor / algo / log 字段；算法和日志使用实时运行值。底层分多次短输出，避免 100 字节缓冲截断；浮点使用 9 位有效数字，保留 float32 精度。
- `IMPORT_OK` 表示固件确认应用并保存；随后读取 `ML GETCFG`，逐项比较全部参数。上位机要求完整起止标记和全部字段，缺失、截断、未知字段、超时或值不一致均报错。
- **当前寄存器参数仅保存，尚未写入芯片**：`config_import.c` 更新 `g_config` 并保存 Flash，但调用的 `sensor_manager.c::sensor_start()` 只初始化数据和标定，没有使用导入值调用寄存器配置。启动扫描调用的 `MLX90393_begin()` 仍使用 `MLX90393_DEFAULT_CONFIG`，因此重启也不能保证导入寄存器值生效。需要下位机将配置应用到实际与参考传感器，并处理失败回执。上位机已传递完整参数，但不能替代缺失的下位机应用步骤。

## 可视化与数据

在 **数据记录 → 导出日志 .log** 下载当前页面的串口通信日志（UTF-8，含 BOM）。日志按时间顺序记录连接参数、全部完整接收行（RX，保留原始日志前缀并包含采样行）、发送命令（TX）、上位机状态及错误。时间戳使用明确标注的 UTC ISO 8601 格式。断开后仍可导出，重连会追加新会话；导出不会清空记录，也不受界面 150 条事件或 12,000 个采样点的限制。过长而被解析器丢弃的串口行记录为警告。

日志在当前页面内存中保存，刷新或关闭页面会清空，请在长时间采集过程中及时导出。此功能从更新页面后的首次连接开始记录，无法补录此前未留存的串口数据。**导出数据 CSV** 仍单独导出采样数值。

三维视图独立绘制形变曲面：Z 的正负控制隆起或凹陷，XY 控制局部倾斜，边缘保持固定，零输入恢复平面。最近 100 帧合成幅值的 P95 用于归一化，|Z| 决定颜色。曲面是单点数据的示意形变，并非实测空间形貌。

箭头沿各网格点的局部下降坡度指向曲面低处，凹陷周围的箭头向凹陷汇聚，长度随坡度变化；平坦处或极值点不绘制无方向箭头。箭头尖端低于起点，避免跨过凹陷后反向上坡。箭头外形和颜色参考 DISPLAY 的 `force_3d_page.py`。顶部 **箭头** 开关仅控制箭头并保存偏好，不影响曲面起伏和坐标轴。暂停采集后曲面保持最后一帧；没有数据时显示平面。

启动默认进入设备模式，未连接时不生成数据；演示模式仅在手动选择后启动。演示模式与设备数据分开记录；切换来源、重新连接及成功导入配置后重置缓存。最多保存 12,000 点。CSV 包含经过时间、接收时间、XYZ、来源及单位；XYZ 读数、曲线提示及 CSV 单位统一使用 `N`（牛顿）；这项界面约定不额外缩放串口数值。采集频率显示接收速率，不代表固件硬件时钟。

## 开发与验证

仅修改后端 C# 时需要重新生成可执行文件（使用 Windows 自带编译器）：

```powershell
powershell.exe -NoProfile -File gui/web/bridge/build.ps1
node --test gui/web/tests/core.test.cjs gui/web/tests/import.test.cjs gui/web/tests/bridge.test.cjs
```

自动测试覆盖解析分包、样例兼容、参数校验、命令排队、ACK 一致性、取消、设备重启、Flash 失败、启动失败、读回不一致及本地 HTTP 命令限制。协议测试使用模拟固件；实际传感器寄存器及 Flash 写入仍需实机验证。
