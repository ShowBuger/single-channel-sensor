# 算法阶段化与精度改造：软件首批交付

> 当前 MA03 行为已更新：1.3.0 仅使用 v2，删除 legacy 算法构建路径，标定固定 300 个有效样本。以 [MA03 v2-only 说明](MA03仅使用v2算法说明.md) 为准；下文两档并存、默认 legacy 的内容为首批交付历史及其他板型行为。

日期：2026-11-19，固件版本 1.2.0。设计依据为 `固件重构设计方案.md` 第 17 节；本记录区分软件验证和硬件验收。

## 已实现

- `firmware/src/app/algo_pipeline.[ch]`：无 HAL、板型、RTOS、串口依赖的阶段表；输入、参数、标定和每通道状态显式传入。算法热路径不打印日志。
- legacy 表保持历史顺序及预测公式，保留 `data_process()` 回放入口。原黄金文件不变，70 组 × 100 个样本最终输出逐位一致。参考不再执行死区、Z 裁剪、映射、静止归零。
- v2 表按 S0–S9 串接：有效性校验、板级方向矩阵、零偏、可选鲁棒尖峰处理、时间对齐及带符号增益、IIR、组合噪声回差死区、独立 Z 负半轴取绝对值、标度、按时间静止归零。
- S3 使用独立轴的历史中值、残差 MAD、阶跃确认及超时解锁，两个配置档默认都不开启。legacy 不使用 S3。
- 时间化：legacy 窗口容量按名义速率换算，并剔除超过 `window_ms` 的旧点；稳定持续时间、v2 IIR 和衰减使用实际时间间隔。无时间戳回放仍用历史 10 Hz 行为。
- 参考调试开启时才计算参考平滑，结果不回馈补偿；开关不重置实际信号的滤波状态。
- 采集任务将读数及元数据按值入队，处理任务不再把旧包写回 `sensor_data[0]`。配置、采集、处理通过互斥锁串行化；标定请求转交 T_ACQ 执行，命令任务等待最终结果。
- 去掉 T_PROC 的二次 10 ms 输出限流；队列满及配置屏障丢弃的样本计数可查询。读取状态/配置等命令不会主动清空采样队列。
- AK09974C 溢出、TMAG POR/DIAG、通信错误、转换超时和主机触发配对偏差进入有效性路径；无效输入不更新滤波/补偿历史。稳定持续计时会中断。
- v2 标定按 `calib_ms` 运行，Welford 估计均值及样本标准差，要求至少 90% 尝试有效。记录版本、有效数/总数、开机相对时间、实际标定速率、温度可用性及 FNV-1a 校验。
- Schema 6（96 字节）：校验旧 Schema 5 的 56 字节记录后，在 RAM 中迁移并补入 legacy 默认参数；显式保存时才写新布局。损坏记录不能迁移为有效配置。
- Web 接收两种样本格式，`valid=0` 只发出无效样本事件，不把零插入曲线。配置预览、导入导出、读回支持新增参数；旧文件不自动加入新字段，仍可给旧固件使用。

## 参数与默认值

`algo.profile` 可用 `legacy`/`v2` 或 `0`/`1` 设置，GETCFG 返回数值。新设备和迁移设备均默认 legacy；协议格式也默认 legacy，两者互相独立。

| 字段 | 默认值 | 限制/含义 |
|---|---:|---|
| profile | 0 | 0=legacy；1=v2 |
| window_ms | 500 | 1–500；legacy 窗口最多 50 点 |
| stable_ms | 1000 | 稳定持续时间 |
| tau_ms | 950 | 静止归零衰减时间常数 |
| tau_lp_ms | 220 | v2 IIR 时间常数 |
| calib_ms | 1000 | 100–10000；仅 v2 按时长标定，legacy 固定收集 300 个有效样本 |
| spike_med_ms | 50 | 最大 50；3–5 点中值预测 |
| spike_mad_ms | 500 | 最大 500；3–50 点残差窗口 |
| spike_confirm_ms | 30 | 至少 2 个连续同向且彼此接近的候选点 |
| spike_hold_ms | 300 | 不小于阶跃确认时间 |
| spike_k | 5 | v2 MAD 倍数，与旧 `algo.spike` 无换算关系 |
| stab_k | 3 | 稳定噪声倍数 |
| kx / ky / kz | +1 / −1 / −1 | 背景补偿增益，各轴绝对值最大 100 |

旧 `algo.dead`、`algo.stab`、映射和 8 位 `algo.flag` 接口保留。bit0–6 延续现有开关，v2 bit6 完整控制 Z 负半轴取绝对值；bit7 控制 v2 尖峰处理。bit8/9 尚未开放，未将 FLAG_RES 扩展为 16 位。

legacy 在无时间戳的 10 Hz 回放上逐位一致；有时间戳、较高速率运行时采用 500 ms / 1000 ms 等时间参数，**不保证与旧版 100 Hz 下的逐样本输出一致**。为保持旧浮点累加次序，legacy 窗口仍重新求和，未改成 O(1) 累加和；v2 IIR 为 O(1)。

S0 在两档中都剔除 NaN/Inf/异常大值，而不把它们替换为零进入平均；这是相对旧版 NaN 补零的显式行为变化。原黄金样本覆盖有限输入及 valid=0，不含 NaN 补零的兼容保证。

## 开发测试方式

以下为可用串口命令示例，本次开发未执行烧录或修改现场设备：

```text
ML STOP
ML SET algo.profile v2
ML SET algo.tau_lp_ms 220
ML SET algo.kx 1
ML SET algo.ky -1
ML SET algo.kz -1
ML FORMAT v2
ML START
ML REFOUT 1
ML STATUS
ML PROF
```

`ML START` 会按当前配置档重新标定；保持传感器静止。legacy 收集 300 个有效样本，采用 Welford 在线均值和样本方差、16 位计数；H743 快速读取时按至少 10 ms 间隔采集，100 Hz 下约 3 秒，实际耗时取决于采样速度和重试。v2 仍按 `calib_ms` 时长标定。`ML CALIB` 在运行中执行同样的标定流程。参数需要保存时再用 `ML SAVECFG`，格式及 REFOUT 不持久化。恢复旧档用 `ML SET algo.profile legacy`，然后重新启动标定；协议恢复用 `ML FORMAT legacy`。

不要盲目复用旧死区参数：v2 阈值使用实际与参考组合噪声，再计入平滑后的等效噪声；与旧版只用实际通道 σ 的含义不同。映射开启、bit6 关闭时，v2 保留 Z 符号，Web 配置预览会提示。

v2 样本示例：

```text
S ch=0 seq=123 t=123456 rate=100 valid=1 x=1 y=2 z=3 tr=123400 skew=56 timing=trigger err=0
```

启用 REFOUT 后追加 `rx/ry/rz`（参考平滑后）和 `rrx/rry/rrz`（参考 S2 后）；有真实温度输出的驱动追加 `T`。无效样本输出 `valid=0`、`err` 和占位零，接收方必须按 valid 丢弃数值。错误 1/2/3/4/5 分别为通信、状态故障、超时、配对偏差、数值无效或运算溢出。

`ML PROF` 返回输入/有效/无效数、尖峰/阶跃/强制接受数、各阶段执行次数。`ML STATUS` 返回当前配置档、标定信息、各类错误与 RTOS 队列丢弃数。计数器和标定记录保存在 RAM，重新标定/重启会重置算法计数器；不是持久化校准档案。

新增独立的算法节点工作台 `gui/web/algorithm.html`，支持真实阶段快照、节点开关和配置档切换，使用 `ML NODES` / `ML NODE` / `ML TRACE`。默认不输出节点遥测；开关仅改 RAM。协议、参考支路含义及旧固件实测边界见 [硬件报告与工具说明](硬件实测与算法工具交付_2026-11-19.md)。

v2 标定失败会在最终 `FAIL` 前输出详细信息；标定 `failure` 的 1/2/3 分别表示采集已停止、有效样本不足、有效比例不足。

## 时间戳的实际边界

H743 用 TIM6 的 1 MHz 计数器与 HAL 毫秒 tick 组合为 32 位微秒计数，处理待响应溢出；L4/F1 裸机适配使用 SysTick。时间戳约 71.6 分钟回绕，差值使用模运算。

计时只能补偿一次待响应的定时器溢出；长时间屏蔽中断导致多次溢出时无法恢复丢失的 tick，仍需硬件测量中断延迟。

两颗传感器通过串行 I2C 顺序触发，不能宣称硬件同步。记录的是触发命令开始时刻，也未修正整笔 I2C 事务和内部转换延迟。主机单次触发模式允许用独立触发时间作一阶参考外推；暂以 5 ms 为软件配对偏差上限，需要实测后整定。

连续模式记录的是主机观测时间，`timing=observed`，**不将这个偏差当作真实采样偏差做外推**。当前 MA03 默认连续模式因此使用增益补偿，但不启用时间外推。`rate` 是名义调度速率，实际速率必须用时间戳/序号测量。

## 验证和剩余工作

运行方式见 `tests/README.md`。软件验证包括原 legacy 黄金样本、v2 合成激励和配置/标定集成测试、AK/TMAG 模拟回归、Web 测试，以及三板编译。[合成对比报告](算法合成对比报告.md)已给出噪声、阶跃和增益失配场景的结果；它不是硬件精度报告。

节点工具加入后的验证：算法测试 28/28；legacy 黄金回放 70 组 × 100 样本；Web 测试 55/55；浏览器流程 2/2。此前软件首批的 TMAG 模拟回归 15/15，AK 模拟回归 10 项通过、1 项可选未链接接口跳过。H743、L432、F103 均编译成功。H743 普通构建 Flash 77,276 字节、RAM 36,576 字节；F103 Flash 63,128 字节（96.33%），后续功能增加需关注容量。

尚未完成的设计项：

1. 使用同一组真实双传感器原始数据做 legacy/v2 对比；测试实际噪声、配对偏差、阶跃、尖峰误剔除率、DWT 耗时、任务栈水位及长期运行。
2. 实测安装方向后配置 board 矩阵；目前三个 board 均为单位矩阵。
3. 温度补偿分段表、实测系数及 Flash 迁移；本次只有温度输入/可用性和标定温度记录，未启用温补。
4. `ML CALIB GAIN` 自动最小二乘增益标定及激励质量判定；本次支持显式设置 K，未声称完成自动增益标定。
5. 校准数据的独立持久化档案、16 位标志扩展、独立日志/监督任务及 L4/F1 完整 RTOS 对齐。
6. 主监测页的 REFOUT 可视化控件；独立算法工作台已支持各节点的实际/参考工作向量曲线，主监测页仍未加入 REFOUT 曲线。

默认配置档切换仍需独立验收。11 月 19 日已对板上的旧 1.1.0 固件完成硬件协议和速率实测；新 1.2.0 尚未烧录，本次不以模拟器测试代替新固件的硬件 100 Hz 或精度验收。
